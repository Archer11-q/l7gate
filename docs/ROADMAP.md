契约第 1 节的目录清单里点名这份文件承担"**五阶段 + 每阶段门禁结果**"，而契约第 4 节的设计原则是：**只在阶段门禁通过时才拆下一阶段的任务**——因为 S2 之后的任务内容取决于 S1 实测暴露的缺陷，提前拆解只会写成幻想中的任务表（所以 `TASKS.md` 的 S2–S5 行至今只有一句话目标，没有子任务）。这份文件因此有两个用途：门禁的**判定结果**记在这里，门禁**留下的债**也记在这里，且后者必须带证据指向（哪个数字、哪个文件、哪一节）。

### 一句话门禁判定

**转发链、响应语义、背压动作、策略插入点这四件事在 S1 都成了可断言的命题**，而且每一条都有反证（sanitizer 会报警、`read_disarmed_connections` 会等于 1、TSan 会红、`✗` 计数不是 0 时脚本会失败）。**SLO #1 没有达标**，SLO #2/#3 连测量条件都还没凑齐（100k 长连接要 S2 的连接模型 + `ulimit`，Nginx 基线要 Docker）——这三句话是 S1 门禁的全部结论，多一句都没有数支撑。

### S1 实测暴露出来的、S2 必须处理的债（每条都指向一个数）

| 债 | 实测证据 | 为什么归 S2 |
|---|---|---|
| 单 Reactor 的排队放大 | 增量 p99 30–38 ms，而 `延迟 ≈ 连接数/QPS` 两组都贴合到 1.4–3.6% 内；50 并发对照下增量只有 1.370 ms（每请求成本 ≈36 µs 不变） | 分摊并发 = 多 Reactor + 连接池，就是 S2 的全部内容 |
| 取样带宽大于待测改动的效果 | 同一份 S1-07 binary 复跑，直连 p99 自己漂了 **11.3%**，四份增量极差 **27%** | S2 的任何性能结论必须先建立"同机交替、每改动至少两轮"的取数规程，否则改了也说不清 |
| 每连接内存有一笔没归因的差额 | 128 条空闲从 S1-06 的 5.31 涨到 S1-07 的 **5.81 KiB/连接**，而对象只涨 8 B（`sizeof=520`） | SLO #2 的判定要到 100k 才做，那时这 0.5 KiB 直接决定 50 GB 还是 51 GB |
| 停读线在回环上从不触发 | 三次标准口径里 `high_water_hits`/`pause`/`resume`/`read_disarmed` **全为 0**；第一道墙是网关自己的 `SO_SNDBUF ≈1.9 MiB` | 256 KiB 这个默认量级要在跨机链路（S4 的 wrk 跨机组）才知道合不合适 |
| pipeline 语义没有支撑 | 一批 400 条 pipelined 请求里带 `Connection: close` 的那条，在**第一条响应完结时**就兑现了（同批字节账完全相等，所以不是丢数据） | 需要请求-响应配对模型，S2 建池时一并决策（要 ADR） |
| 优雅停止不排水在飞连接 | `SIGTERM` 语义 = 不再接受 + 退出循环；S1-07 冒烟阶段三**故意**留着一条卡住的连接并断言 `live_connections=1` | 真正的停止（排水 + 超时兜底）与连接池同期做 |
| filter 链的两笔显式返工 | 没有"目标上游"字段（路由 S3 要它）、没有响应方向钩子（日志/改写 S5 要它）——今天都没有读者 | 各自和它的读者一起进来，不预先造字段（S1-03 的"配置写了、代码没读"教训） |
| `ulimit -n`=10240 | 100k 场景的第一行会是 `accept_errors`，不是内存 | S2/S3 之前必须由环境侧解决，记 `ENVIRONMENT.md` 第 4 节 |
| Docker 未接入 / perf 可用性未验证 / p999 无工具 | `ENVIRONMENT.md` 第 2、4 节的 ❌ 与 ⚠️；wrk 4.1.0 与 hey 0.1.4 的分位表都只到 99% | Nginx 基线（S3/S5）、尾延迟归因（S5）、p999 判定，分别卡在这三项上；后两项属新依赖/新授权范围 |

## 待项目所有人裁决的事项（S1 收尾时提出，未自行处理）

1. **卡点三**：SLO #3 的判定基线要不要允许"只交自测 QPS"过关到 S5。S1 交的是自测 QPS（21,582.93 / 57,170.55），Nginx 基线因 Docker WSL Integration 未开而跑不起来——这是环境授权项，不是代码问题，我不自己找替代路径（8.2 禁令一）。
2. **卡点四**：SLO #2 的分母「连接数」在代理拓扑下的歧义（一个客户端连接配一条回源连接 = 两个连接对象？）。`TASKS.md` 卡点四原文保留，判定到 S2/S3 才做，但口径要先定。
3. **取样规程**：是否接受"同机交替、每改动至少两轮"作为 S2 之后性能结论的强制取数规程（依据：四份增量极差 27% > 待测改动效果）。
4. **p999 的取数手段**：换/加发压工具属新依赖，按 8.2 禁令三需 ADR + 裁决；在那之前 SLO #1 的 p999 半边按"无法判定"记，不按"达标"也不按"未达标"记。
5. **pipeline / `Connection: close` 语义**：要不要在 S2 的连接池工作里一并定义（要 ADR），还是明确宣布 S1–S2 不支持 pipeline、并在解析层拒掉。
