# ADR-08 · 不做响应缓存

- 状态：已采纳（拒绝记录）
- 日期：2026-10-26
- 相关：契约 1.3

## 我明确不做什么

不实现 `proxy_cache` 式的响应缓存，也不做 ATS 式对象缓存。

## 为什么这不是「偷懒」而是「形态选择」

**缓存是另一种网关形态，不是本网关的一个功能。** Apache Traffic Server 的全部商业价值就在缓存层——命中路径上它甚至不联系上游，延迟特征、内存模型、失效语义、可观测指标的整个坐标系都换了。

如果我加缓存，会出现一个我无法解释的结果：压测 QPS 大幅上升、p99 大幅下降，但这两个改善**不来自流量治理**，而来自「这个请求我根本没转发」。契约第 2 节测的是「网关自身引入的增量尾延迟」和「与 Nginx 的差值归因」，缓存命中会让这两个指标失去意义——尾延迟治理的价值被缓存命中率盖住，差值归因也不再是解析/内存/连接管理/系统调用的比较。

而我的三个数字就是全部价值锚点。所以我拒绝它，理由不是「太难」，是**它会摧毁我要测的东西**。

## 这条为什么要写出来，而不是默默不做

契约 1.3 的每条不做项都要有 ADR，因为「默默不做」和「想过之后不做」在评审时一眼能看出来。别人问「你为什么不加缓存」时，答案是「加了它我的 p99 指标就不再度量流量治理」，而不是「我没做」。

## 顺带澄清一个容易混的东西

上游连接复用（S2 的上游连接池）**不是**缓存。它省的是 TCP 建连成本，响应内容仍然每次真实从上游取，不改变尾延迟的归因路径。这个区别我会写在 README 里，避免被误读成「你说不做缓存，但你不就在复用连接吗」。
