# ADR-25 · 分位那一格的来源：读落盘摘要的旁路 exporter，不是网关自报

- 状态：已采纳（2026-11-03，项目所有人选了这条岔路）
- 相关：S5-03、ADR-24（指标暴露面）、ADR-17（测量手段变更要留记录）、契约 4.2 第 1 层、SLO.md #1

## 这一节在裁什么

S5-03 的验收句 ① 要「面板六格每格指到具体指标键名并显示非空曲线」，而六格里那一格「p99/p999」
**在网关这一侧没有来源**。我实测过，不是推断：本轮起一台 armed 网关（`health`+`circuit`+`rate_limit`
+`--config-reload-ms`+`--metrics-port`）抓一次 `/metrics`，**101 个 `# TYPE` 全是整数 counter/gauge，
没有一格是时延**。理由写在 ADR-24 第一节——「我们的指标全是整数 counter/gauge，分位由客户端自己算，
SLO 那条线已经这样跑了三个阶段」。所以这不是实现漏了一格，是那条裁处的**必然后果**：
面板要么引用一个不存在的键，要么这条「非空曲线」由别的东西供给。

TASKS 的 S5 拆解里写着「S5-03 没有 ADR 前置」，那句话说的是**镜像不用换**
（`prom/prometheus:v2.51.2`、`grafana/grafana:10.4.2` 由契约 9.1 锁 tag、已 `docker image inspect` 证实就位）。
它没有覆盖「分位那一格怎么有数」这个问题——**这一条就是那条缺口，所以我按 ADR-17 的先例补记录，
并把「拆解说无 ADR 前置而我仍然写了一份」当成偏离照记在这里**，不当作没发生。

## 一、我选择什么

**`tools/l7gate_bench_exporter`：一个只读已落盘压测摘要、把它们发成 Prometheus gauge 的旁路进程。**

- 它读的正是 SLO #1 那两条线各自产出的东西：`scripts/bench/s1-p99.sh` 的 `s1-p99.summary.txt`
  （wrk 主口径，p50/p75/p90/p99 毫秒 + `增量 p99=` 那一行）与 `scripts/bench/s1-p999.sh` 的
  `s1-p999.summary.txt`（自研 HDR 客户端，p50/p99/p999/p9999 微秒 + `增量 p999 =` 那一行 +
  每臂的**观察者占单核**那一列）。**数据的产地一个字不改**：那两个脚本、HDR 桶、128 µs 分辨率、
  取样规程，全是 S1/S2 就立着的既有口径，本任务不新增、不修改任何测量条件（禁令二）。
- 它自己服务一个 HTTP `/metrics`，Prometheus 抓它，就像抓网关那个端口一样。抓取通路我实测过：
  本发行版下容器不共享 WSL 网络命名空间，但 `--add-host=host.docker.internal:host-gateway` 之后
  容器**确实能读到宿主上绑 `0.0.0.0` 的端口**（实测取回 `# HELP elapsed_ms` 那行；
  `172.17.0.1` 那一路是 `Connection refused`）。这条通路写进 S5-05 的 compose 时同样不许换成
  `network_mode: host` 那种在这台机器上不成立的东西。
- 面板上那一格的标题与 `# HELP` 写死三重限定：**谁产的分位**（wrk 4.1.0 的分位表只到 99% /
  p999 由 `l7gate_c100k` 的 HDR 桶产出）、**什么档**（每个 series 自带 `conns`/`window_ms`/`canonic`/
  `preset`/`workers` 标签，非标准档不得冒充标准档）、**分辨率**（本档 HDR 桶 ≈128 µs/请求，
  B-018 那句限定原样带）；同时保留 B-009 那条事实——**1000 并发那档的 p999 判「取不到」，卡点是
  观察者单核饱和**，所以那一格发的是「读数 + 观察者占单核」两个数，而不是只发读数。

## 二、否掉的三条（各自的代价我算过，不是嫌麻烦）

- **那一格留空并如实判「取不到」**：诚实、零新代码，但验收句 ① 当场不成立（六格变五格），
  而且它把「SLO 判定的取不到」（B-009，专指 1000 并发那档）误升成「任何档都取不到」——
  100 并发闭环那档的 p99/p999 是**有读数的**（B-006 结果三、B-019、B-020 都落在盘上）。
  投影那一条与 SLO 判定的那一条是两个不同的命题，我不能因为后者判不了就把前者也说成没有。
- **`prom/pushgateway`**：少写一个 HTTP 服务端，但它是契约 9.1 表外多出来的一个镜像和一个 tag
  （禁令三要 ADR、而动锁定表归项目所有人裁），并且把口径从 pull 改成 push——为了演示面去改采集模型，
  方向反了。
- **给网关加 histogram/summary 族**：面板会有一条真正连续的曲线，代价是翻掉 ADR-24 已裁的
  「分位由客户端自己算」、动每请求热路径（B-019 那条整数等式当场换定义、历史读数不可比）、
  动 60 格 golden 与键集合，而且 TASKS 已经把「每请求成本的独立尺」列在**候补、不在确认之列**。
  这不是 S5-03 的体量。

## 三、不造数的五条硬规矩（这一节是这个 ADR 真正要钉的东西）

面板最容易撒谎的地方，是它把「推算」和「没读到」都画成一条曲线。五条都落进 exporter 的实现：

1. **缺字段就不发那一格，绝不补 0**。摘要里那一行不存在或解析不出数 → 那一个 series 整个不出现。
   理由与 `s1-p999.sh` 里那句 `p999 取不到（值=空）：这一格没有读数，别用 0 冒充` 同源。
2. **每个数带着它的来路**：`batch` 标签就是 `build/bench/` 下那个目录名，另发一格
   `l7gate_bench_sample_time_seconds`，值取摘要首行那个 ISO 时间戳。任何人可以在盘上 grep 到同一个数。
3. **`canonic` 标签原样带**（摘要首行自己写着 `canonic=0/1`）。它是「这一档能不能进 SLO 判定」的
   那把闸，面板不许把它抹平；非标准档在图上和标准档混在一起的读法要由标签可区分。
4. **观察者那一列必须一起发**（`l7gate_bench_observer_cores`）。B-009 的教训是「卡点是观察者不是
   被测方」，一个不带观察者负载的分位曲线比没有曲线更坏。
5. **exporter 不产生负载、不读被测方内存、不碰 `src/`、不进网关任何计数**。它是仪器，
   和压测上游、`l7gate_c100k` 同族（口径第 3 条：仪器不进被测方）。

## 四、labels 的口径为什么这里可以用，而网关那一族不能用

ADR-24 第五节拒绝把每目标那族点号键改成 label 形态，理由是「键名不许改」是对**网关那 101 键**的承诺。
exporter 这一族是新立的仪器面，没有历史读数要保护，所以按 Prometheus 的正常习惯做成
一个族 + `quantile`/`arm` 标签。这不构成对 ADR-24 那条例外的翻案：**网关侧一个键名、一个 TYPE 都没动**。

## 五、成本（这一格怎么说才算诚实）

- **不进每请求热路径**：exporter 是另一个进程，网关的每请求等式不受它影响；B-019 那两臂量的是
  「开/不开 `--metrics-port`」，本任务不新增网关侧的任何东西，所以那两条读数原样有效。
- **但同机抢 CPU 是真的**：Prometheus 抓取 + exporter 解析都在同一台 16 核机上，而 SLO #1 的
  卡点恰恰是观察者单核饱和。所以立一条顺序规矩：**要么先跑压测再起监测，要么把「监测面在跑」
  这一档显式标成同机干扰、不得与已归档的 canonic 读数混比**。S5-03 的冒烟按前者排。
- exporter 自己那格的解析成本：读的是几十 KB 的文本、每 `scrape_interval` 一次，不在被测方路径上，
  本轮不单独记账（记账对象是网关，不是仪器自己的桌子）。

## 六、定义域到哪里为止（S5-05 不许越过）

compose 里这个 exporter 是**第四个独立服务**：它读宿主机 `build/bench/` 的挂载副本，
不进网关容器、不共享网关的内存、不因为 compose 而改成读 `/proc` 或读 `ReactorStats`。
ADR-10 追加节对热重载的定义域（不重载限流参数、不换链的形状、mysql 组与文件重载不叠加）
在这里同样不许被面板措辞越过去：S5-03/S5-05 的面板与 compose 里出现的每一条结论，
都要能在 `BENCHMARK.md` / `SLO.md` / 落盘摘要里找到同一个数。
**面板是眼睛，不是账本**——终判（S5-07）读的仍是落盘输出，不是 Grafana 上的曲线。

## 七、验收句 → 断言落点

| S5-03 验收句 | 落点 |
|---|---|
| ① 六格每格指到具体键名 + 非空曲线 | `smoke-s5-03.sh`：从 `dashboard.json` 里逐格取出 PromQL 表达式，打到 Prometheus 的 `/api/query`，**六格各自断非空**（表达式与面板同源，不另写一份查询） |
| ② 亲眼看到 429 且与 `rate_limit_rejected` 逐数对得上 | 同一脚本：注入超速率流量后，直接抓网关 `/metrics` 的 `rate_limit_rejected` 与 Prometheus 里那条 series 的最后一个采样**逐数相等**；再做一次扰动（多打 N 条）两边同涨——等式两边一个是被测方自报、一个是仪器读数，互背书形状同 §15.1 |
| ③ 亲眼看到熔断把后端摘掉 + ⑥ 限定语 | 同一脚本：杀一台上游 → `health_ejected_now` 0→≥1、`circuit_half_open_now` 有跳变；断言面板「上游健康度」那格的描述里含 `health_ejected_now=0 不能读成没有坏后端` 那句（措辞入库靠断言，不靠我记得） |
| ④ 分位格的口径与 SLO.md 一致 + 分辨率限定 | 同一脚本：断 `dashboard.json` 那一格的 title/description 含「谁产的分位 / conns / 窗口 / ≈128 µs」四样，且 exporter 发的 `canonic`、`observer_cores` 两格在 Prometheus 里查得到 |

## 八、阳性验证清单（能红才叫绿）

- **E1 缺字段补 0**：让 exporter 在解析不到某个分位时发 `0` → 「那一格 series 不出现」那条断言必须红。
- **E2 面板与查询分家**：把 `dashboard.json` 里某一格的表达式改成一个不存在的键 →
  「六格逐格非空」必须红（这条守的是「我另写一份查询糊过去」那个形状）。
- **E3 拿仪器替代被测方**：429 那条等式改成「exporter 自己算一遍 vs Prometheus」→ 必须红
  （被测方自报那一半不许被我自己的读数替掉）。
- **E4 把 non-canonic 画成判定**：抹掉 `canonic` 标签 → 口径断言必须红。
每条第一版没红就先弄清为什么没红，不改用例凑红（§15.3 / §16.3 / §20.2 / §21.1 四次都是这条）。

## 九、明确不做

不新增网关侧指标；不改 `s1-p99*.sh` 的参数与判据（禁令二）；不引 pushgateway/node_exporter 等
契约 9.1 表外镜像；不为了面板把 HDR 桶搬进 `src/`；不在本任务量 exporter 自己的资源占用（它是仪器，
且第五节已把「同机抢 CPU」这条以顺序规矩处理，而不是以一条没测的账处理）；
不做 Grafana 告警、不做多面板、不做管理后台（契约 1.3）。
