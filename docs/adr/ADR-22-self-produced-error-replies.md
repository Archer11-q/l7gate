# ADR-22 · 回源失败的自产错误响应（S4-02）

## 一、三个触发形态与状态码

S4-02 之前，回源拿不到上游时请求**留在下游缓冲里一言不发**：`ensure_upstream` 返回空、`forward_request` 返回 false、`forward_pending_requests` 当成"以后再来试"。connect 已经确定失败的那条请求永远等不到"以后"——S2-06 的 71,769 条客户端 timeout 就是这条路径的实测形状。本 ADR 把三个触发点各自换成一条自产响应：

| 形态 | 触发点 | 状态码 | 计数格 |
|---|---|---|---|
| connect 失败 | `start_connect` 同步 kFailed；或 `kConnecting` 期间 `SO_ERROR != 0` | **502 Bad Gateway** | `gateway_replies_connect_failed` |
| 全员被摘（回退后的最后防线） | 同上，但被选目标在**失败揭晓那一刻**已被策略摘除 | **503 Service Unavailable** | `gateway_replies_all_ejected` |
| 本地连接 / fd 预算耗尽 | `connections_.size() >= max_connections`；或 `epoll_ctl` 注册上游失败 | **503 Service Unavailable** | `gateway_replies_over_capacity` |

三条语义规则写死：

1. **三个新格与 `gateway_replies_sent` 同一口径**（S1-06）：只有响应真的进了下游出向缓冲才计；一次表态只进一格，互斥。容量分支不查健康状态——它没尝试过网络，"这是谁的错"的答案是本地资源。
2. **502 与 503 的分界是"上游不可达"与"本网关没有可用上游/容量"**：502 说"我替你试了，对面不通"；503 说"我这边此刻给不出一个可用后端"。与 Envoy 的 `no_healthy_upstream → 503` 同源。
3. **全员被摘的归类看失败揭晓时的健康状态，不看重选目标时的快照**。摘除到期或另一个 worker 的探活恢复会让同一请求从 `all_ejected` 格落到 `connect_failed` 格；两格之和才是这条路径一共发了多少表态。归类的精度边界照记。

## 二、全员被摘：回退保留，自产响应是"最后防线"而不是入口拒绝

S3-03 的行为原样保留：候选集为空时 `LoadBalanceFilter` **回退全员集合**（ADR-12 的"故意保留一段错误，换取不自我放大"）。本 ADR 不在 filter 入口对全员被摘直接 503，理由：

- 摘除判据可能失准。回退让一条请求仍有机会落到"被误判死、其实活着"的成员上；入口拒绝会把判据失准放大成第二次故障——这正是 S3 阶段要解决的真问题。
- 安全阀（默认 10%、floor 语义）已经保证全员被摘只发生在小到"一个都不能摘"的组被配成高比例、或 N<10 的组整体死掉时。这个频率下，"先试一次再表态"的价格是毫秒级 connect 失败，换来的是不误杀。

所以"最后防线"的位置在**尝试失败之后**：回退选的成员连不上 → 503 + `gateway_replies_all_ejected`。它在客户端侧的语义与入口拒绝相同（一条完整 503），但保留了"如果那个成员其实活着，请求照样成功"这一条路。

## 三、动作与写通道

1. **复用 S1-06 的 `fail_pair_with_reply`**：解链 → 自产响应排进下游出向 → `gateway_replies_sent`（及新格）→ 上游 `kDiscardOutbound`、下游 `kFlushThenClose`。connect 从未完成 = 没有任何上游字节到过下游，所以 502/503 一定是这条请求的**第一条**响应，不伪造（S1-06 的资格规则）。
2. **同步失败需要一个三态返回，不能挤进 `kBlocked`**。`ensure_upstream` 的返回从裸 `shared_ptr` 改成携带"要不要表态"的三态通道；`forward_request` 相应返回 `kForwarded / kBlocked / kReplied`，`forward_pending_requests` 把 `kReplied` 映射成 `kFailed`。把"发过表态并已关连接"混进 `kBlocked` 的后果是：调用方会以为"以后再来试"，对一个已经进入 kClosing 的连接继续泵。
3. **异步失败（kConnecting + SO_ERROR）走同一套表态**：找到配对下游就 `fail_pair_with_reply`，没有下游（它先关了）就只关闭上游——没有表态对象时不造响应。
4. **健康联动与归属顺序**：先读"失败揭晓时是否已被摘"（归类），再 `note_health_failure`——反过来读的话，这一次失败自己触发的摘除会把普通过 connect 失败误归成 `all_ejected`。
5. **顺带修一个配对账漏洞**：`register_connection` 失败分支原来先清 `downstream->peer_fd` 再关上游，`note_upstream_paired` 的 +1 没有对应的 −1（least_conn 会慢慢把这条后端读成"永远最忙"）。新实现把 `note_upstream_paired` 挪到注册成功之后；这条不是本任务的目标，是同一段代码里躲不开的账。

## 四、放弃什么 / 不做什么

- **不对上游已经回出的 5xx 做任何改写**：错误如实透传。安全阀挡住的成员继续接流量（ADR-12 的语义），它的 5xx 原样到客户端——**不伪造成功**，也不把它改写成 502。`gateway_replies_*` 三格在"上游回了 500"时全是 0，这一点有用例钉着。
- **不做重试**：connect 失败的重试边界归 S4-06（ADR-23）。本 ADR 的失败分支是它的挂接点——重试落地时先重试、仍失败才走到这里。
- **不在 body 已开始透传后自产响应**：S1-06 的资格规则不变；body 空闲超时仍以断流表态（ADR-21）。
- **不做"错误率判据"**：那是 S4-05；本 ADR 只处理"确定拿不到上游"这一族。
- **不设重试预算、不排队等上游**：拿不到就表态，等 = 把失败拖成超时。

## 五、代价与边界（照记）

- **一条下游上 pipelined 的多条请求共用一条连不上的上游时，只回一条 502/503 然后关连接**。客户端以 `Connection: close` 知道后续请求没有答复；这是 ADR-16 / S1-05 "close 之后的请求不承诺"的既有口径，不是本 ADR 新开的例外。
- **容量格的两个子形态可断言程度不同**：`max_connections` 命中能在 ctest 端到端造出来；`epoll_ctl` 注册失败没有可控注入手段，它与前者共用同一条表态语句，端到端不可断言——照记。
- **`all_ejected` 的归类在"无组、只有 default_target 且健康表已装配"的退化配置里也会触发**：那种配置下请求不经过候选集，被摘的目标照样被选。此时这一格仍然诚实地回答"我们试了一个策略已经写死的成员"。
- **表态不等于恢复**：503 不改变摘除状态；探活/到期恢复照旧（S3-03）。
- **S2-06 旧债的结账位置**：E=1 名义档重跑（100k 下游、回源容量 28,232）进 `FAULT-INJECTION.md` §13；那里记客户端拿到的表态计数与零 handshake-timeout，而不是把 502 冒充成"容量问题解决了"——容量口径那件事归 ADR-17。
